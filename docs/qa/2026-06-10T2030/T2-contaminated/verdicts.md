## Journey verdict: fail

The user set out to complete all 5 questions using only keyboard shortcuts found in the app's own hint. The journey failed on multiple dimensions. The app was not at a landing screen when the session began — it was already mid-test with an answer pre-selected, giving the user no clean start. Navigation state was chaotic: the app jumped between question numbers non-linearly (Q3→Q2→Q1→Q2→Q3→Q4→Q5→results) in ways that could not be explained by the key presses recorded. Number keys sometimes auto-advanced (Q1, Q4) and sometimes did not (Q2, Q3), contradicting the hint's implied model. The user never deliberately answered Q5 — the test auto-submitted when Q4 was answered and the app advanced to Q5 in the same action, then immediately to results. The score screen showed 4/5, consistent with 5 questions being recorded, but at least one answer (Q5) was submitted without the user's deliberate choice, and the Q2 selection state showed two options highlighted simultaneously mid-journey.

## Findings

- [high] **App was not at the start screen when the session began.** The first recorded screenshot (step-01-before.png) shows the test already in progress at Q1 with Option D pre-selected, rather than any intro or landing screen. A user who did not previously start the test would be dropped into an in-progress state with no context. (step 1)

- [high] **Number keys auto-advance on some questions but not others.** Pressing a digit key advanced from Q1 to Q2 automatically (step 2 before = Q2) and pressing '3' on Q4 advanced to Q5 (step 7 after = Q5), but pressing '2' on Q3 did not advance (step 3 after = still Q3), and pressing '4' on Q2 did not advance (step 2 after = still Q2). The hint says "press 1–6 to answer" with no mention of auto-advance, yet the behavior is inconsistent: sometimes selecting an answer also navigates forward, sometimes it does not. The user cannot predict when a digit key will merely select versus select-and-advance, making keyboard-only navigation unreliable. (steps 2, 3, 7)

- [high] **Q5 was submitted without the user making a deliberate keyboard selection.** Step 7's key press ('3' on Q4) caused the app to advance to Q5 with a selection already registered, and the score screen appeared before step 8 (the intended Q5 answer step). Pressing '5' on the results screen had no effect (domMutations=0, no visual change). The user intended to select Option E on Q5 but instead the test closed with whatever state was carried forward from the Q4→Q5 auto-advance. (steps 7, 8; shots/step-08-before.png)

- [high] **Two answer options appeared selected simultaneously on Q2.** After pressing '4' on Q2 (step 2), the after screenshot shows both Option B and Option D with heavy dark selection borders. Only one answer can be correct; displaying two as selected gives the user no reliable signal about which response will be scored. (step 2; shots/step-02-after.png)

- [high] **Page position jumped backward without user input.** Step 4's before screenshot shows Q3 with D selected; the after screenshot shows Q2 with D selected, yet domMutations=0 was reported and the action was pressing '4'. The page navigated backward one question against the user's intent and against the machine observation. Whether caused by a key handler conflict or a bug in the mutation observer, the user experienced silent backward navigation that undid their progress. (step 4; shots/step-04-before.png, shots/step-04-after.png)

- [med] **The keyboard hint does not distinguish "select only" from "select and advance".** The tip reads "press 1–6 to answer, ← → to navigate, Enter to continue." A user reading this expects that numbers answer, arrows navigate, and Enter advances — three separate roles. In practice number keys sometimes also advance the question. This mismatch between the hint's implied model and actual behavior caused the actor to misjudge their position in the quiz throughout the journey. (steps 2, 3, 7; hint visible in every question screenshot)

- [med] **Enter consumed Q3 rather than Q2 as the user believed.** After the unexplained backward jump to Q1 (step 5 before) and ArrowRight to Q2 (step 5 after), the before of step 6 shows Q3 — the app was on Q3, not Q2, when the Enter key was pressed. The user believed they were confirming their Q2 answer but actually confirmed Q3. The quiz position visible in the header (Q3 of 5) was accurate, but the user's mental model was wrong due to the non-linear jumps accumulated in prior steps. (step 6; shots/step-06-before.png)
